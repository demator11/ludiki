# Казино под микроскопом

Версия 0.3: два интерактива — монетка и «Почти получилось». Анимированные экраны участников, живой проектор и пульт ведущего с управлением с телефона. Python / FastAPI, обычные HTML/CSS/JS, WebSocket. Без Node-сборки, CDN, внешних шрифтов и сторонних сервисов для QR-кода.

## Открыть сейчас

После запуска:

| Адрес | Для кого |
| --- | --- |
| `http://localhost:8000/` | Обзор концепции |
| `http://localhost:8000/admin` | Пульт ведущего |
| `http://localhost:8000/screen` | Проектор, отдельная вкладка/окно |
| `http://localhost:8000/play` | Участник; адаптировано для телефона |

При первом запуске создаётся случайный пароль ведущего. У участников пароля нет, имя необязательно.

## Запуск через Python

В PowerShell из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python main.py
```

Пароль ведущего:

```powershell
Get-Content .\data\admin-key.txt
```

Если зависимости уже установлены, достаточно `python main.py`. Для PyCharm можно запускать `main.py`; рабочая папка — корень проекта. По умолчанию сервер слушает только `127.0.0.1:8000`, чего достаточно для ngrok на том же ПК.

## Запуск через Docker

```powershell
docker compose up --build -d
docker compose exec ludiki cat /app/data/admin-key.txt
```

Перед запуском освободите порт 8000, остановив Python-версию, если она работает. Пароль и ответы Docker-версии хранятся в отдельном именованном томе `ludiki-data`; они не совпадают с локальной папкой `data` Python-версии.

```powershell
docker compose logs --tail 50 ludiki
docker compose down
```

Обычный `down` сохраняет том. Не используйте `down -v`, если нужны результаты. Контейнер работает непривилегированным пользователем. Предполагается один экземпляр/один worker; несколько процессов с общим JSON не поддерживаются.

Изменения Python, HTML, CSS или JS в Docker применяются командой `docker compose up --build -d`. Тексты и программа из пульта применяются сразу. После изменения фронтенда обновите страницу браузера.

## Доступ через ngrok

После настройки ngrok для своей учётной записи:

```powershell
ngrok http 8000
```

1. Скопируйте выданный адрес `https://…ngrok-free.app` (или `.dev`).
2. В пульте откройте «Настройки» и вставьте базовый адрес в «Адрес для телефонов и QR-кода», без `/play`.
3. Откройте `/screen` на проекторе. QR теперь ведёт на публичный адрес `/play`.
4. Проверьте ссылку с телефона через мобильный интернет, затем через сеть аудитории.

Пульт и проектор на ноутбуке можно оставить на localhost: их соединения тогда не проходят через туннель.

По документации ngrok, проверенной 20.11.2026, Free включает 20 000 HTTP-запросов и 1 ГБ исходящего трафика в месяц, до 4 000 HTTP-запросов в минуту. WebSocket поддерживается обычным HTTP-туннелем. На первом входе через браузер бесплатный ngrok показывает промежуточную страницу Visit; заранее предупредите участников об одном дополнительном нажатии.

Для 20–25 подключений этого достаточно при свободной квоте и нормальной связи. Здесь нет постоянного HTTP-опроса: только действия пользователя и WebSocket-обновления. Одна сессия содержит сотни действий и небольшие JSON-сообщения, а не видео. Фактический трафик зависит от числа подключений, переподключений, повторов и уже использованной месячной квоты. Локальная нагрузочная проверка не гарантирует доступность ngrok у конкретного оператора/в конкретной вузовской сети.

- https://ngrok.com/docs/pricing-limits/free-plan-limits
- https://ngrok.com/docs/using-ngrok-with/websockets

## Без ngrok, по IP

**Одна Wi-Fi-сеть:** у компьютера должен быть доступный остальным устройствам локальный адрес, например `192.168.1.10`.

Для Python:

```powershell
$env:HOST = '0.0.0.0'
python main.py
```

Для Docker скопируйте `.env.example` в `.env`, поставьте `BIND_ADDRESS=0.0.0.0` и перезапустите Compose. На телефонах откройте `http://<IP-компьютера>:8000/play`; этот базовый адрес также укажите в пульте. Возможно, потребуется разрешить входящий порт 8000 в брандмауэре. Вузовская Wi-Fi-сеть может изолировать клиентов друг от друга — проверить заранее. Localhost на телефоне указывает на сам телефон, а не на ноутбук.

**Через интернет по IP:** понадобится доступный внешний IP, настройка NAT/проброса порта и брандмауэра. При CGNAT простой проброс не работает. HTTP не шифрует пароль пульта и ответы; для публичного доступа используйте HTTPS-туннель или VPS с HTTPS reverse proxy. Для первого показа ngrok проще. В Docker доверие forwarded-заголовкам предполагает, что опубликованный порт доступен только доверенному прокси; не используйте текущий контейнер как открытый интернет-сервис без reverse proxy и ограничения доступа к порту.

## Демонстрация с ботами и резерв

Подробный сценарий проведения и действий при сбое — [RUNBOOK.md](RUNBOOK.md). Требования к хостингу и отдельная конфигурация Linux/Docker/HTTPS — [deploy/README.md](deploy/README.md).

1. Войти в `/admin`, открыть `/screen` отдельно.
2. Нажать «Перейти к демонстрации», выбрать модуль и «Запустить ботов».
3. Боты проходят сцену постепенно. Доступны пауза, скорость ×1 / ×2 / ×4 и «Завершить действия ботов». Результаты раскрывает ведущий.
4. В монетке можно отдельно запустить 100 000 раундов и переключать источник цифр.
5. «Повторить эту сцену» в демонстрации сбрасывает только ботов этого модуля. «Вернуться к аудитории» возвращает сохранённую живую сцену и её ответы; открытый сбор будет на паузе.
6. Через «Скачать программу» / «Загрузить программу» перенести тексты и настройки в локальную копию до пары. Ответы и пароль в этот файл не входят.
7. После предварительной Docker-сборки `start-local.cmd` запускает готовую локальную копию без скачиваний. На ноутбуке должен работать Docker Desktop.

Вымышленные оценки ботов явно помечены. Они иллюстрируют интерфейс и ход обсуждения, а не моделируют психологию реальных людей. Боты не добавляются к реальной выборке. Для телефонной проверки откройте `/play`, присоединитесь и завершите демонстрацию в пульте.

## Содержание модулей

### По ту сторону казино

Старт 200 условных очков, ставка 10, при успехе возвращается 19 вместе со ставкой. Независимая вероятность 1/2. На телефоне 4–20 раундов (по умолчанию 8). Очки и исходы считает сервер; математическое ожидание игрока −0,5 очка на ставку, то есть −5% оборота. Никакой подгонки живых результатов под проигрыш нет. Отдельная симуляция 100 000 раундов — модель, не продолжение реальных участников. Положительный результат казино здесь до любых расходов бизнеса.

### Почти получилось

Два заранее подготовленных проигрыша: обычный и визуально близкий к совпадению. У каждого выплата 0 при ставке 10. Каждый участник оценивает оба исхода по шкале 0–10; порядок чередуется между A/B. Считаются только полные пары. Участник запускает барабаны; они останавливаются по очереди, после чего появляется шкала оценки. Это два подготовленных анимированных исхода, не случайная выборка спинов. На проекторе до разбора виден только прогресс без личных оценок.

## Что уже есть в пульте

- На телефоне три вкладки: «Управление» (сцена и основные кнопки), «Экран» (превью проектора), «Ещё» (QR, настройки, боты, резерв и экспорт).
- Любая сцена, следующий модуль, пауза, приём ответов и раскрытие.
- Сброс текущей сцены, новая сессия с подтверждением, репетиция на вымышленных ответах.
- Редактирование названия, подзаголовка, итогового тезиса и скрытой заметки ведущего.
- Включение/выключение и изменение порядка модулей.
- Публичный адрес и QR-код, количество активных подключений, список псевдонимов и журнал действий.
- Точная уменьшенная копия экрана проектора: общий рендерер слайда и стили, включая графики и таблицы. Превью рассчитано на формат 1280×720; у самого проектора размер может отличаться.
- Экспорт агрегированных результатов JSON без cookie-ключей и индивидуальных анкет.
- Пароль ведущего, повторное подключение телефона, сохранение состояния после перезапуска.

Админка исправляет содержание и управляет мероприятием. Она не исправляет программные ошибки: для этого редактируются файлы. Расчёты и правила — `core.py`; API и сохранение — `main.py`; экраны — `static/app.js`; анимации и общий живой экран — `static/experience.js`; оформление — `static/style.css`.

## Обновление с 0.2

Пересоберите контейнер и обновите страницы пульта, проектора и телефонов. Пароль и данные в томе сохраняются. Программа автоматически сокращается до монетки и «Почти получилось»; тексты этих сцен сохраняются. Старые ответы отключённых экспериментов остаются в данных и экспорте. Старые файлы программы можно импортировать: недоступные сцены исключаются.

Анимации не меняют результат: исход монетки определяет сервер, а идентификатор и время действия не дают повторно проигрывать старый бросок после обновления страницы. Поддерживается системная настройка уменьшения движения. Звука нет.

## Ограничения

Одна общая комната, без нескольких мероприятий одновременно. До 80 зарегистрированных участников как ограничение прототипа; проверено 20 участников и 5 дополнительных подключений. Автовосстановление WebSocket; нет HTTP polling fallback. Ответы сохраняются в локальном JSON с атомарной заменой файла. Вход ведущего после перезапуска сервера нужно повторить. Потеря cookie телефона создаст нового участника. Псевдонимы и ответы хранятся на сервере до сброса сессии. Не разворачивать с несколькими workers/репликами.
